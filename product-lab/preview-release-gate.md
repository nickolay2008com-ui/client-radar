# Evo Product Lab — Preview Release Gate

Назначение: не считать Upgrade Room, preview, демо или оффер готовым, пока он не прошёл минимально достаточную проверку и не ведёт к одному понятному коммерческому шагу.

## 1. Source-of-truth gate

Персональный актив разрешён только при наличии в Evo:

- company_record_id;
- interest_event_id;
- точной цитаты или явно зафиксированного запроса клиента;
- полной истории контакта;
- подтверждённой проблемы клиента;
- коммерческого статуса и владельца следующего шага.

Если хотя бы одного пункта нет, персональный актив не создаётся. Допускается только улучшение общего компонента.

## 2. Fact / hypothesis split

На первом экране должны быть отдельно обозначены:

- **Подтверждённый факт** — только то, что следует из Evo, переписки или публичной страницы клиента;
- **Гипотеза** — осторожное предположение о возможном улучшении;
- **Неизвестно** — данные, которых пока нет и которые нельзя подменять догадкой.

Запрещено указывать неподтверждённые потери, рост, конверсию, сроки окупаемости, отзывы и гарантии.

## 3. Minimum solution gate

Preview должен показывать только один минимальный сценарий:

1. один подтверждённый пользовательский запрос;
2. один путь решения;
3. один ожидаемый результат;
4. один обратимый следующий шаг.

Не добавлять интеграцию, кабинет, аналитику, оплату, автоматизацию или дополнительные экраны, если они не нужны для проверки основной гипотезы.

## 4. Mobile gate

Проверить ширины 360, 375 и 390 px:

- нет горизонтального скролла;
- основной смысл виден без масштабирования;
- текст не мельче 16 px;
- интерактивные элементы не меньше 44×44 px;
- CTA виден после краткого объяснения пользы;
- форма запрашивает только необходимые данные;
- клавиатура не перекрывает CTA;
- длинные URL, email и названия не ломают сетку.

## 5. Link gate

Проверить вручную:

- публичный URL открывается без авторизации;
- нет 404, редирект-циклов и пустых экранов;
- все внутренние ссылки ведут на ожидаемые страницы;
- внешние ссылки открываются безопасно;
- CTA ведёт ровно к заявленному действию;
- после отправки формы пользователь видит подтверждение и следующий шаг.

Локальный файл, скриншот или описание не считаются опубликованным preview.

## 6. Clarity gate

За 10 секунд пользователь должен понять:

- что это;
- какую его подтверждённую проблему решает;
- что произойдёт после нажатия CTA;
- сколько усилий требуется от него сейчас;
- что не будет изменено без согласования.

Удалить технические термины, внутренние названия и лишние обещания.

## 7. Trust gate

Обязательно указать реальные границы первого шага:

- без доступа к админке, если он не требуется;
- без изменений основного сайта до согласования;
- без оплаты до согласованного коммерческого этапа;
- без использования клиентских данных вне согласованного сценария;
- что является демонстрацией, а что уже работает.

Нельзя использовать вымышленные логотипы, цифры, отзывы, кейсы или статусы интеграции.

## 8. CTA gate

Разрешён один основной CTA. Он должен:

- требовать одного простого решения;
- описывать конкретный следующий шаг;
- быть обратимым и низкорисковым;
- не требовать от клиента подробного ТЗ, команды или предварительной интеграции;
- иметь одного владельца результата.

Хорошие форматы:

- «Одобрить этот сценарий для пилота»;
- «Выбрать один вариант»;
- «Подтвердить страницу для теста»;
- «Дать один недостающий ввод»;
- «Назначить 15-минутную проверку».

## 9. Commercial next-step card

Перед выпуском заполнить:

- решение клиента сейчас;
- что Ally AI сделает после согласия;
- что требуется от клиента;
- срок следующего шага;
- цена или условие её расчёта, если вопрос цены уже подтверждён;
- критерий успеха;
- критерий остановки;
- ответственный;
- дата следующей проверки.

## 10. Verification record

Записать в Evo:

- asset_type;
- public_url;
- checked_at;
- checked_mobile_widths;
- checked_links;
- confirmed_fact;
- hypothesis;
- trust_boundary;
- primary_cta;
- commercial_next_step;
- result_status: draft | verified | shared | approved | rejected;
- owner;
- next_review_at.

## Release decision

Актив можно считать готовым только если одновременно выполнены:

- источник интереса прослеживается до Evo;
- использована только подтверждённая проблема;
- мобильная версия проверена;
- ссылки проверены;
- польза ясна;
- границы доверия указаны;
- есть ровно один CTA;
- следующий коммерческий шаг записан;
- рабочая ссылка сохранена в Evo.

## Method improvement

После каждого цикла добавить одну строку:

- weakness.found;
- improvement.applied;
- lesson.saved;
- next_cycle_rule.

Следующий цикл обязан применить предыдущий `next_cycle_rule` до создания нового актива.
